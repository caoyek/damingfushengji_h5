> **版本规范声明**：  
> 本设计文档 100% 基于真机逆向底层动态库 `libEnvRelay.so`（符号 `CBattle`, `CActionMgr`, `CActionFactory`, `CDlgBattle`, `CPnlSelSkillInfo`, `CRoleInfo::MsgSendChooseSkill`）、客户端原版布局资产（`Battle.xml`, `PlayerInfo.xml`, `SelSkillInfo.xml`）以及官方底表 `BattleSetting.csv`, `BattlePos.csv`, `SkillAction.csv` 真实还原。

## 一、 战斗系统核心架构：服务端权威演算与客户端纯回放

### 1.1 架构定性与权责边界
通过对 `libEnvRelay.so` 中 `CBattle::ProcessBattleInfo(Json::Value &root)`（偏移 `0x00535B0C`，占用 17.3 KB 代码段）的反编译深度解析，确立了如下绝对事实：
* **服务端（Server）权威计算整场战斗**：
  1. 所有战斗的**先后出手顺序、是否触发技能、具体伤害数值、暴击/闪避/格挡判定、怪物AI反击技能、Buff状态结算及胜负掉落**，100% 在服务端瞬时模拟完成；
  2. 客户端严禁在本地自行运算伤害公式（彻底杜绝改内存攻击力、锁血等外挂）；
* **客户端（Client SO）纯回放渲染器 (Battle Replay Engine)**：
  1. 客户端接收服务端下发的一整套包含所有战斗回合的 JSON 战报数据流；
  2. 客户端根据 `SkillAction.csv` 驱动时间轴：按序播放双方入场移动、施法动作、跳跃近战或原地远程特效、播放对应 `.ogg` 技能音效、飘出伤害掉血字样、触发 `baoji.swf` 暴击或 `shanbi.swf` 闪避、震屏及死亡淡出；
  3. **跳过战斗功能**：服务端下发的 `see_result_button_state`（`see_click`, `see_vip_click`）支持普通/VIP玩家直接跳过播放动画，瞬间拉起胜利或失败结算框。

## 二、 角色出战配置：每人物限制装配 3 个出战技能

### 2.1 技能出战装配机制 (`PlayerInfo.xml` / `SelSkillInfo.xml`)
* **界面入口**：玩家在角色属性主面板（`PlayerInfo.xml`）右侧，设有【选择出战技能】专区（TextId `400025`）；
* **数量上限限制**：每个出战角色（主角或伙伴武将）在技能库中虽然可以学会并升级多达十几种主动战斗技能，但**进入战斗时最多且仅能勾选装配 3 个主动战斗技能**；
* **底层协议流**：
  - 勾选触发 `CPnlSelSkillInfo::OnChkSkill`（偏移 `0x00256154`）；
  - 本地维护装配列表 `CRoleInfo::SetUse`，校验上限不超过 3 个；
  - 触发 `CMsgRole::SendChooseSkill` 上报服务端，同步更新服务端该角色的 `used_skills` 数组字段。
* **战斗轮转规则**：
  - 角色在战斗中仅能释放这 3 个已装配的技能或基础普攻；
  - 依据当前拥有的气力值（MP / 怒气）与技能优先级判定当前回合出招。

### 3.1 字段核心释义
* **`teams`**：攻防两端参战角色阵容属性初始快照；
* **`rounds`**：**完整推演回合流数组**；
  - `att_id`：本回合行动出手者；
  - `def_ids`：受击目标 ID 列表（单体或全体群伤）；
  - `skill_id`：本回合使用的技能 ID（0 为普通攻击，>0 为专属绝招）；
  - `howmuch`：本次招式扣除的真实气血伤害值；
  - `is_shock`：是否触发暴击大招震屏；
  - `is_remote`：是否原地远程施法（0 为跳到敌人面前近战攻击，1 为原地远程发波）；
  - `is_cri` / `is_dodge`：分别驱动客户端播放 `baoji.swf` 与 `shanbi.swf` 特效；
* **`win_id` / `lost_id`**：对局胜负判定结果；
* **`rewards`**：战斗结算掉落（经验、银两、战功、装备与宝石星级）。

## 四、 战斗九宫格阵型与时序参数

### 4.1 九宫格像素站位 (`BattlePos.csv`)
战场双方各有 6~9 个固定站位，客户端根据坐标渲染立绘：
* **攻方阵位 (`att1~6`)**：前排（上、中、下）、后排（上、中、下）；
* **守方阵位 (`def1~6`)**：前排（上、中、下）、后排（上、中、下）。

### 4.2 严格时序参数 (`BattleSetting.csv`)
* **入场移动**：300ms
* **攻击移动总耗时**：800ms
* **动作帧间隔**：30ms
* **受击击退**：400ms / 10px
* **暴击震屏**：60ms / 15帧
* **死亡淡出**：1000ms（闪烁3次淡出）
* **胜利结算展示**：500ms（播放 `snd_battle_victor.ogg`）
* **失败结算展示**：1000ms（播放 `snd_battle_fault.ogg`）

## 五、 本地单机/离线模式下的战斗引擎落地方案

针对本项目跨端复刻（微信小游戏、Web Canvas、单机 Android 壳）：
1. **前端职责纯粹化**：前端专注于 `BattleVisualizer`，完全对齐官方 `BattleSetting.csv` 时序与动画播放；
2. **后端/本地推演引擎 (`CombatSimulator`)**：
   - 在本地或服务端实现与官方闭源逻辑一致的轻量推演器；
   - 规则：按全场出手者 `Speed` 倒序排序；根据攻守双方攻防公式与 3 技能配置生成 `rounds` 数组；
   - 输出标准战报 JSON 数据流直接喂给前端回放，完美实现脱机可玩与多人联网双重兼容。

## 六、 服务端推演引擎算法实现规范 (Authoritative Simulator Engine)

鉴于网龙原版的服务端代码闭源运行于远程服务器，复刻工程必须在后端（`server/` Node.js）及本地单机引擎中**完整自主实现这套推演算法**。算法输入攻守双方快照，输出标准 `rounds` 战报：

### 6.1 完整推演状态机时序 (Simulation Loop)
```text
[发起战斗请求] 
      │
      ▼
1. 初始化战场环境：
   - 攻守双方载入九宫格（攻方 att1~6，守方 def1~6）；
   - 读取双方十维属性快照（生命、气力、物攻/魔攻、物防/魔防、速度、命中、闪避、暴击）；
   - 读取双方每人装配的最多 3 个出战技能（used_skills）。
      │
      ▼
2. 回合大循环 (Round Loop，最多 30 回合，超限防死锁判定平局/守方胜)：
   ┌── 按照全场存活角色的 Speed (出手速度) 从大到小构建行动队列。
   │    │
   │    ▼
   │   遍历每个行动角色：
   │   - 检查自身是否处于眩晕等失能状态；
   │   - 判定出招类型：若当前 MP 充足，从 3 个出战技能中按优先级/概率选取技能，扣除 MP；否则打出普通攻击；
   │   - 目标索敌 AI (Targeting)：
   │     * 单体攻击：优先攻击正对面同排最前列目标；若同排全灭，攻击邻排前排；
   │     * 群体横扫：锁定目标所在整排；
   │     * 全体法伤/治疗：锁定敌方或己方全员存活目标；
   │     * 嘲讽优先：若场上有防将释放了【嘿，孙子！】且在持续时间内，强制攻击该防将；
   │   - 命中与闪避判定：
   │     * 骰点判定：命中率 = max(10%, min(100%, 95% + (攻方Hit - 守方Dodge) / 等级系数))；
   │     * 若未命中：生成 is_dodge = 1，本次伤害为 0，记录战报；
   │   - 暴击与格挡判定：
   │     * 暴击率 = max(5%, min(100%, (攻方Crit - 守方Toughness) / 等级系数))，暴击倍率 150%，标记 is_shock = 1；
   │     * 防御方格挡率判定：格挡成功伤害折半（50%），防将触发反弹伤害；
   │   - 伤害计算：
   │     * 实际伤害 = max(1, (攻方对应攻击力 * 技能倍率 - 守方对应防御力 * 防御抵扣系数)) * 暴击/格挡修正；
   │   - 结算扣血与阵亡：
   │     * 扣减受击者当前 HP；若 HP <= 0，目标阵亡并移出本场后续行动队列；
   │   - 记录当前 Action 至 rounds 战报数组；
   │   - 胜负即时检测：若守方全灭 -> 攻方胜；若攻方全灭 -> 守方胜，立即跳出循环。
   └── 重复下一回合。
      │
      ▼
3. 结算发奖：
   - 判定胜利者 win_id 与失败者 lost_id；
   - 结算副本预设经验、金币、战功与随机掉落物品（装备、宝石）；
   - 输出完整 JSON 战报供客户端纯回放。
```
